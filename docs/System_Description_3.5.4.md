## 3.5.4 The Intervention: Design and Implementation of the Researcher-Developed Software

The intervention artefact produced under Research Objective 2 is a bilingual (Sinhala and English), level-wise assistive mathematics platform, named *Read & Play*, developed for Grade 4 learners identified with dyscalculia. The platform was designed so that each of its principal features corresponds to one of the four theory-derived independent variables set out in Section 1.9 (IV1–IV4), and so that its ordinary operation automatically records the usage data required by the engagement instrument (Section 3.5.3). In this way the software functions simultaneously as the treatment delivered to the Digital Learning Group (DLG) and as an instrument for the unobtrusive capture of engagement evidence, without adding tasks that would increase the learner's cognitive load. Its content is aligned to the Sri Lankan Grade 4 national mathematics syllabus, and its structure follows the basic-to-advanced progression justified by the Defective Number Module hypothesis (Butterworth, 1999), which holds that remediation should rebuild numerical understanding from its foundations.

### System architecture and technology

The software was developed as a browser-based web application. The learner-facing client was built with React, and a server implemented in Node.js (Express) manages authentication, application logic, and data storage in a PostgreSQL database. This architecture was chosen for reasons that bear directly on the study rather than for engineering convenience. Because the application runs in a standard web browser, it requires no installation and operates on the modest hardware and network conditions typical of Sri Lankan primary schools, which supports the classroom implementation stage (Section 3.6, Stage 3). Because all interaction passes through a central server and database, every learning event is recorded automatically and consistently at the point of use, which is what makes the software-generated component of the engagement instrument feasible. Content is presented through picture-based illustrations and on-screen animations, and a reading-supportive typeface and calm colour scheme are used throughout to reduce visual and reading barriers for learners who may also experience reading difficulty.

### Operationalisation of the four independent variables

The design translates each independent variable into concrete, observable features.

Multi-sensory numerical representation (IV1) is realised by presenting every concept through three coordinated channels: visual animated representations of quantity (for example, sets of countable objects, ten-frames, number lines, and place-value displays), auditory narration of all instructions and item text through the device's speech synthesis, and interactive on-screen manipulation in which the learner taps or selects and receives an immediate response. These channels deliberately link quantity, spoken number word, and written symbol, as prescribed by the Triple-Code Model (Dehaene, 1992).

Adaptive level-wise scaffolding (IV2) is realised through a graded structure in which content is organised from basic to advanced. A dedicated foundational module rebuilds core number sense (counting, quantity comparison, numeral recognition, and the meaning of mathematical symbols) before arithmetic is introduced, and each activity is offered at successive difficulty levels. Progression is governed by mastery: a threshold level of accuracy is required to unlock the next level, and the difficulty subsequently presented is adjusted in response to the learner's performance. This keeps each learner working just beyond their current independent ability, consistent with the Zone of Proximal Development (Vygotsky, 1978).

Bilingual delivery (IV3) is realised through a persistent language control that renders all instructions, narration, and item text in either Sinhala or English at the learner's selection. Because the verbal code in numerical processing is language dependent (Dehaene, 1992), delivery in the learner's stronger language is treated as an intervention feature in its own right rather than a convenience.

Immediate feedback and reduced cognitive load (IV4) are realised by presenting a single concept at a time in short practice rounds, without time pressure, and by returning corrective feedback together with brief spoken encouragement after every response. Instructional narration can be replayed on request, providing on-demand audio support during self-study. These choices are intended to keep working-memory demand within capacity and to reduce the frustration associated with mathematics anxiety, in line with Cognitive Load Theory (Sweller, 1988).

### Data captured for the engagement measure

During use, the software records each learner's activity in the database and makes it available as a per-student comma-separated export for entry into the statistical software used in analysis (Section 3.8). The recorded fields correspond to the software-generated usage logs specified in the engagement instrument (Section 3.5.3): time-on-task (both the duration of each session and the active time accumulated within activities), the number of activities and levels completed, and the number of attempts and retries per task. In addition, the platform records the response time to each individual question and a log of interaction events, and it offers a brief, age-appropriate self-report of mood at the start and end of a session that complements the motivation questionnaire. Together these fields provide behavioural evidence of on-task engagement and persistence for the DLG, which is compared with the equivalently observed engagement of the Traditional Learning Group in the test of Hypothesis 4. A teacher-facing dashboard summarises each learner's progress and engagement and produces the export, supporting both the monitoring of implementation and the visibility of progress beyond the lesson.

Table 5 summarises how the platform's features map onto the four independent variables and the data captured for analysis.

**Table 5. Mapping of system features to the independent variables and the engagement data captured**

| IV | Design feature as implemented | Underpinning theory | Data automatically logged |
|----|-------------------------------|---------------------|---------------------------|
| IV1 | Coordinated visual, auditory, and interactive representation of quantity, word, and symbol | Triple-Code Model (Dehaene, 1992) | Interaction events; response accuracy per item |
| IV2 | Basic-to-advanced modules with a foundational number-sense stage; mastery-gated, performance-adjusted progression | ZPD (Vygotsky, 1978); Number Module (Butterworth, 1999) | Levels and activities completed; attempts and retries; scores per level |
| IV3 | Learner-selectable Sinhala or English for all narration and text | Verbal code, Triple-Code Model (Dehaene, 1992) | Language of delivery; per-item performance by language |
| IV4 | Single-concept tasks, no time pressure, immediate feedback and encouragement, replayable spoken support | Cognitive Load Theory (Sweller, 1988) | Time-on-task; per-question response time; feedback and support usage |

In summary, the researcher-developed software operationalises the four theory-based design features as working components of a single bilingual, level-wise platform, delivers the Grade 4 curriculum content to the experimental group across the implementation stage, and captures the behavioural engagement data that, alongside classroom observation and the motivation questionnaire, supports the comparative evaluation of effectiveness and engagement in Stage 4.
